# 审查系统毕业论文写作

## 依据与使用范围

开始撰写或润色前，读取随包的[写作风格](references/writing-style.md)，按本次任务选用有关部分；学校模板、用户明确的题目和篇幅要求优先。学习论证方式，不模仿作者原句。

本 skill 提供写作与核验方法，不附带论文库、项目实现或实验数据。在用户指定位置或当前工作区查找本次正文、已确认方案、原始文献和实验记录。缺失材料时明确缺口，继续处理不依赖它们的表达；不将示例当作用户已经完成的研究。

## 执行方式

1. 确定任务属于开题、论文章节、综述、润色还是审阅，锁定用户要求的修改范围。
2. 涉及系统能力或贡献时，核对最新确认的题目、实现与实验记录，区分已完成、拟开展和未验证的内容。旧方案不自动代表当前状态。
3. 涉及引用或数字时，使用[原文核验与文献卡](references/source-verification.md)。已有文献卡仅作导航，回查所引原文的页、章节、表格及必要上下文；关键表格提取不清时查看原页面。材料不足则标明待核验，不声称已经读过原文。
4. 完成用户要求的正文或审阅意见，再核对时态、指标、范围及证据。只读审阅给出位置、原因和最小修改建议；用户要求修改时在授权范围内落盘。

## 按任务组织内容

| 任务 | 输出重点 |
| --- | --- |
| 开题报告 | 研究问题、已有工作边界、拟采用的方法与验证设计。使用计划语气，预期成果写可交付物，不预设效果。 |
| 毕业论文 | 分开说明实现、功能测试、方法实验与业务效益。方法交代输入输出、来源、关键判断及失败处理；结果保留比较条件与限制。 |
| 文献综述 | 按任务和方法比较研究对象、证据范围及与本课题的关系，避免逐篇摘要拼接。 |
| 润色 | 保留业务含义、方法、限定条件及引文对应关系，调整结构和措辞；事实不足单独标明。 |
| 审阅 | 指出计划冒充成果、结论外推、指标错配或引用不支持判断的具体位置，给出最小改写建议。 |

## 交付前核对

每个重要结论应能回到原文或本项目证据。分清原作者报告、整理者分析、本课题假设和本系统实测结果；摘要、表格和结论采用一致的统计口径。没有统计检验时写具体差值与条件，不使用统计意义上的“显著”。

交付正文或文件，并简要说明实质修改、所用依据及待核验项。尚无实验数据时提供明确标注的框架或方法描述，不产出看似完成的结果。
